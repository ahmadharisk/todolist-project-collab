Cara kerja Todo List

Aplikasi todo sederhana: tampilan dibuat dengan React, data dilayani API Express, dan disimpan di SQLite. Halaman ini menjelaskan teknologi yang dipakai dan perjalanan data dari klik di layar sampai tersimpan di database.

React→ fetch /api/todos→ Express→ SQLite
Frontend

React + Vite

Menampilkan daftar, menangani klik, dan memanggil API. Tidak menyimpan data sendiri, semua sumbernya dari server.

Backend

Express

Empat endpoint REST di /api/todos untuk ambil, tambah, ubah, dan hapus. Semuanya di satu file server.js.

Database

SQLite

Satu tabel todos dengan kolom id, title, done, dan created_at, tersimpan di satu file.

Teknologi

Enam bagian yang membentuk aplikasi ini, untuk apa dipakai, di file mana, dan kenapa dipilih.

Frontend

React 19

Untuk apa
Menggambar daftar todo dan bereaksi pada klik. Data disimpan di state (todos, title, filter, error), dan layar otomatis berubah setiap state berubah.
Di mana
frontend/src/App.jsx
Kenapa
Cukup komponen App dan TodoItem dengan useState. Tidak perlu library state tambahan untuk aplikasi sekecil ini.
Alat build

Vite 8

Untuk apa
Dev server dengan hot reload, proxy /api ke backend, dan build kode React menjadi file HTML, JS, dan CSS biasa.
Di mana
frontend/vite.config.js
Kenapa
Cepat dan konfigurasinya hanya beberapa baris. Proxy membuat browser merasa frontend dan API satu alamat, jadi tidak perlu mengatur CORS.
Komunikasi

fetch + JSON

Untuk apa
Mengirim request HTTP dari browser ke API. Semua panggilan lewat satu helper api() yang memasang header JSON dan mengubah respons error menjadi pesan di layar.
Di mana
Fungsi api() di App.jsx
Kenapa
Bawaan browser, jadi tidak perlu library seperti axios.
Backend

Express 5

Untuk apa
Server HTTP: membaca body JSON (express.json()), menjalankan 4 route di /api/todos, dan di Docker juga menyajikan file frontend (express.static).
Di mana
backend/server.js
Kenapa
Ringan dan dikenal banyak orang. Seluruh backend muat di satu file pendek, dan express adalah satu-satunya dependensi backend.
Database

SQLite (node:sqlite)

Untuk apa
Menyimpan todo di tabel todos dalam satu file todos.db. Tabel dibuat otomatis saat server pertama kali jalan.
Di mana
DatabaseSync di backend/server.js
Kenapa
Modul bawaan Node 22.13+, jadi tidak perlu install library atau menjalankan server database. API-nya sinkron sehingga kode route lurus tanpa await. Modul ini masih berlabel eksperimental, karena itu script memakai --disable-warning=ExperimentalWarning.
Deploy

Docker Compose

Untuk apa
Membungkus semuanya jadi satu container: build frontend, jalankan Express di port 3001, simpan database di volume.
Di mana
Dockerfile, docker-compose.yml
Kenapa
Cukup satu perintah dan tidak perlu Node terpasang. Build dua tahap membuat image akhir kecil karena alat build frontend tidak ikut masuk.

Arsitektur

Aplikasi bisa dijalankan dengan dua cara. Pilih mode, lalu klik kotak mana saja untuk melihat penjelasan dan kodenya.

Alur data

Coba pakai todo di bawah ini: tambah, centang, klik dua kali untuk edit, hapus, atau ganti filter. Setiap aksi menghasilkan jejak langkah dari React sampai SQLite dan kembali lagi. Datanya simulasi di browser, jadi tidak butuh server.

      API

      Semua endpoint ada di /api/todos dan bertukar data dalam JSON. Klik satu baris untuk melihat contoh request dan respons. Contoh curl memakai port 3001, yang berlaku di mode dev maupun Docker.

      Struktur folder

      Klik file atau folder untuk melihat isinya secara singkat.

        Cara menjalankan

        Pilih cara yang sesuai. Mode Dev butuh Node.js 22.13 atau lebih baru, mode Docker tidak butuh Node sama sekali.

        1. Terminal 1, jalankan backend di http://localhost:3001: 
          cd backend && npm install && npm run dev
        2. Terminal 2, jalankan frontend di http://localhost:5173: 
          cd frontend && npm install && npm run dev
        3. Buka http://localhost:5173. Data tersimpan di backend/todos.db, dibuat otomatis saat backend pertama kali jalan.
        1. Dari folder utama, build dan jalankan: 
          docker compose up --build
        2. Buka http://localhost:3001. Frontend dan API dilayani dari container yang sama.
        3. Perintah lain yang berguna. Jalan di background: 
          docker compose up -d --build
          Hentikan, data tetap aman di volume: 
          docker compose down
          Hentikan dan hapus data: 
          docker compose down -v
        1. Di Mac, nyalakan mesin Podman dulu: 
          podman machine start
        2. Build dan jalankan, lalu buka http://localhost:3001: 
          podman compose up --build
        3. Selesai mencoba, matikan mesinnya supaya tidak memakan memori: 
          podman machine stop
